# NLL Non-Lexical Lifetimes 非词法生命周期
## 一、先搞懂：什么是「词法生命周期（旧版 Rust <1.31）」
词法 = 代码块 `{}` 的文本范围，生命周期严格跟着**大括号**走。

旧规则痛点：
只要借用变量的词法块没结束，借用就一直有效，哪怕逻辑上后面再也不用这个借用了。
会出现明明代码逻辑没问题，但编译器报「同时存在多个可变借用」。

示例（旧 Rust 编译报错，NLL 之后正常）
```rust
let mut v = vec![1,2,3];
let first = &mut v[0]; // 可变借用1
println!("{}", first);
let second = &mut v[1];// 旧编译器报错：v还被first借用中
```
旧逻辑：`first` 的生命周期到函数末尾 `}`，两块可变借用同时存活 → 冲突。
但人眼能看出来：`first` 打印完就再也不用了，完全可以释放借用。

## 二、NLL 非词法生命周期是什么
Rust 1.31 引入 NLL，核心改进：
**不再以大括号词法范围判断借用存活，而是按「变量最后一次使用位置」截断生命周期。**

规则：
一个借用从创建，到**最后一次读取/使用该借用**为止，之后立刻失效、归还权限。

上面例子在 NLL 下流程：
1. `first = &mut v[0]`：v 借出可变权限给 first
2. `println!("{}", first)`：最后一次使用 first
3. 从此刻起，first 的生命周期直接结束，v 的可变借用权限归还
4. `second = &mut v[1]`：重新可变借用 v，无冲突，编译通过

## 三、核心解决的两类经典报错
### 1. 同一块数据连续多次可变借用（最常见）
```rust
let mut s = String::from("abc");
let a = &mut s;
println!("{}", a);
let b = &mut s; // NLL 允许
```

### 2. match / if let 分支内借用提前释放
无 NLL 时代很多匹配代码会误报借用冲突，NLL 自动优化。

## 四、对比：词法生命周期 vs NLL
### 1. Lexical（词法）
生命周期边界 = 代码块 `{}` 结束
借用存活时间 = 从定义到所在块末尾

### 2. Non-Lexical（NLL）
生命周期边界 = 变量**最后一次使用**
借用存活时间 = 从定义到最后一次访问，提前回收借用权限

## 五、边界例子直观感受
### 示例1：借用中途失效
```rust
let mut arr = vec![10,20];
let x = &mut arr[0];
*x += 1;
// x 在这里用完，生命周期结束
println!("{}", arr[1]); // 可以直接访问arr，无借用冲突
```

### 示例2：大括号不影响，只看最后使用
```rust
let mut data = vec![1,2];
{
    let r = &mut data[0];
    *r += 5;
    // r 最后使用点，生命周期结束
}
// 哪怕还在大括号内，r已经失效，外面随便借用
let r2 = &mut data[1];
```

## 六、NLL 不改变 Rust 安全规则
重要：NLL **只是缩短了借用的存活区间，没有放宽任何所有权安全规则**。
- 同一时间不能同时存在：可变借用 + 其他任何借用（可变/不可变）这条规则没变；
- NLL 只是智能判断「什么时候借用已经没用，可以提前销毁」，减少误报。

## 七、NLL 和 Lexical 的本质区别一句话
词法生命周期看**代码文本的大括号**；
非词法 NLL 看**变量逻辑上什么时候不再被使用**，提前回收借用，大幅减少无意义的借用冲突报错。

## 补充小历史
- Rust 1.31 稳定启用 NLL；
- 现在所有新版 Rust 默认开启，不用额外配置；
- 日常开发遇到的“可变借用冲突”编译报错，基本都是真正的逻辑冲突，而非旧编译器的词法误判。
