本质：
将自己模块内部的东西，重新导出，即重新命名


# 一、先解释链接 `https://docs.rs/tokio/latest/tokio/#reexports`
这个页面是 Tokio 官方文档的**重导出（Re-exports）** 章节，专门列出 tokio 顶层包直接对外暴露的、原本定义在内部子模块里的类型/函数，方便开发者直接 `use tokio::xxx`，不用写深层路径。

文档里的示例：
```rust
pub use task::spawn; // rt feature required
```
含义：
`tokio::task::spawn` 原本在子模块 `task` 下，通过 `pub use` 重导出到 crate 根，你可以直接写：
```rust
use tokio::spawn;
// 等价于 use tokio::task::spawn;
```

# 二、Rust 中 reexports（重导出）是什么
## 1. 语法本质
`pub use 路径;` 就是重导出。
分为两种场景：
1. **同 crate 内部重导出**：把子模块内容暴露到顶层（Tokio 大量用这种）
2. **跨 crate 重导出**：`pub use other_crate::Type;`，把第三方库的类型当成自己库的 API 对外提供

示例分层理解：
```rust
// src/task.rs
pub fn spawn() {}

// src/lib.rs
pub mod task;
// 重导出到 crate 根
pub use task::spawn;
```
外部使用时二选一：
```rust
// 长路径
use tokio::task::spawn;
// 简化路径（靠 reexport）
use tokio::spawn;
```

## 2. 核心作用 & 为什么需要 reexports
### 1）对外提供简洁、统一的 API 入口，屏蔽内部模块结构
库作者可以自由重构内部代码（拆分、合并模块），**不破坏用户代码**。
- 假设 Tokio 某天把 `task` 拆成 `runtime_task` 内部模块；
- 只要保留 `pub use runtime_task::spawn;` 重导出；
- 用户 `use tokio::spawn` 完全不用改，兼容不变。

如果没有 reexport，用户代码全是深层路径，内部一重构所有下游代码全部报错。

### 2）聚合分散功能，降低用户使用成本
以 Tokio 为例：
同步原语在 `tokio::sync`、网络在 `tokio::net`、任务在 `tokio::task`。
库通过重导出把高频 API 挂在顶层：
```rust
pub use net::{TcpStream, TcpListener};
pub use task::spawn;
pub use sync::Mutex;
```
用户直接 `use tokio::{spawn, TcpStream, Mutex}`，不用记忆一堆子模块名。

### 3）封装依赖，隐藏底层第三方实现（跨 crate reexport）
场景：你的库封装了 `bytes` / `futures`，不想让用户直接依赖第三方 crate。
```rust
// lib.rs
pub use bytes::Bytes;
```
用户只需要依赖你的库，直接 `use your_crate::Bytes`，不用手动加 `bytes` 依赖；
未来你切换底层实现，只要保持对外类型名不变，下游无感知。

### 4）区分内部实现和公开稳定 API
库内部可以有大量私有模块、内部工具类型；
只通过 `pub use` 把承诺稳定的 API 暴露到顶层，清晰划分：
- 内部：`crate::internal::xxx`（不保证兼容）
- 公开：`crate::xxx`（重导出，语义化版本保证不破坏性变更）

### 5）简化文档阅读（对应你打开的 #reexports 页面）
docs.rs 会单独提取所有 `pub use` 生成 Re-exports 章节，用户一眼能看到**顶层能直接导入的所有符号**，不用钻进各个子模块翻找常用函数。

# 三、结合 Tokio 看实际收益（对应你提供的文档）
1. **功能模块化拆分**
Tokio 内部拆分为 `task` / `net` / `sync` / `time` 等子模块，方便维护、按需开启 feature；
2. **通过 reexport 抹平模块层级**
不需要用户写冗长路径，同时配合 feature 控制可见性（比如 `spawn` 仅开启 `rt` 才会被重导出）；
3. **API 长期稳定**
哪怕内部模块重构，顶层 `tokio::spawn`、`tokio::TcpListener` 入口永远不变，生态项目无需大规模修改；
4. **文档友好**
`#reexports` 页面集中展示所有顶层快捷导入，新手不用逐个查阅子模块文档。

# 四、补充：reexport 和普通 mod 的区别
```rust
// 仅声明模块，用户只能 use tokio::task::spawn
pub mod task;

// 重导出，额外提供顶层快捷路径 use tokio::spawn
pub use task::spawn;
```
`pub mod` 只是暴露子模块本身；`pub use` 是把子模块里的**具体项**提升到上层命名空间，二者互补。

# 总结
1. Reexports = `pub use`，Rust 用来**转发、提升符号可见性**的语法；
2. 核心价值：**解耦库内部实现与外部调用代码**，简化导入路径、屏蔽底层依赖、保证 API 兼容性；
3. Tokio 的 `#reexports` 文档页，就是把所有顶层快捷导入统一展示，方便开发者快速查找常用 API。
