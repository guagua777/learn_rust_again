# Rust 模块两种目录写法区别
### 背景
这是 Rust 不同版本的模块文件布局规范：**旧版 mod.rs 写法** vs **新版扁平文件写法**

## 写法1：混合写法（sub.rs + sub/文件夹）
- 文件结构
```
src/
├── sub.rs        // 主模块文件
└── sub/          // sub 的子模块目录
    ├── a.rs
    └── b.rs
```
- sub.rs 内部代码：
```rust
// 引用同目录 sub 文件夹里的子模块
pub mod a;
pub mod b;
```
- 本质：**sub 模块本体就是 sub.rs 文件**，同时配套一个同名文件夹存放它的子模块，不再需要 mod.rs

## 写法2：传统 mod.rs 写法
- 文件结构
```
src/
└── sub/
    ├── mod.rs    // sub 主模块文件
    ├── a.rs
    └── b.rs
```
- sub/mod.rs 内部代码：
```rust
pub mod a;
pub mod b;
```
- 本质：**整个 sub 文件夹就是 sub 模块，mod.rs 是这个文件夹模块的入口文件**

## 核心区别
### 1. 入口文件位置
- 写法2：模块 = 文件夹，入口固定是 `mod.rs`，是 Rust 早期唯一支持的文件夹模块写法
- 写法1：模块 = `sub.rs` 单独文件，同名 `sub/` 文件夹仅用来放其子模块，**不再需要 mod.rs**（Rust 1.30 后支持的新版布局）

### 2. 路径引用规则
- 写法2：`mod sub;` → 加载 `sub/mod.rs`
- 写法1：`mod sub;` → 优先加载 **sub.rs**，再去看 sub 文件夹；不会依赖 mod.rs
    - ✅新版推荐：用 `sub.rs + sub/` 布局，减少一堆 mod.rs 文件，目录更清爽
    - ✅旧项目/老教程：常见 `mod.rs` 布局，依然可以正常编译运行（向后兼容）

### 3. 目录观感
- mod.rs 写法：目录里会出现大量 `mod.rs`，容易视觉杂乱
- sub.rs 写法：一眼区分模块主文件（sub.rs）和子模块文件夹（sub/），可读性更好

### 4. 兼容性
- 两种写法**语法功能完全一致**：导出、访问、可见性、pub 规则都一样，仅文件布局不同
- 禁止混用：不要同时存在 `sub.rs` 和 `sub/mod.rs`，会产生冲突、编译报错

## 总结
- `sub/mod.rs`：**传统文件夹模块模式（旧写法，向后兼容）**
- `sub.rs + sub/`：**新版扁平模块模式（官方推荐写法）**
- 功能无差异，仅文件组织形式不同，新项目优先用 sub.rs 写法，老代码可继续保留 mod.rs

### 最简参考结构（新版推荐）
```
src/
├── main.rs
├── sub.rs
└── sub/
    ├── foo.rs
    └── bar.rs
```
```rust
// sub.rs
pub mod foo;
pub mod bar;
```
```rust
// main.rs
mod sub;
use sub::{foo, bar};
```






### 核心原理
Rust 的模块系统有一条基础规则：**必须先通过 `mod 模块名;` 声明/引入模块，编译器才会去加载对应模块文件、把模块纳入当前 crate 的模块树，否则编译器根本不知道 `sub` 这个模块存在**。

#### 1. `mod sub;` 的作用
```rust
// main.rs
mod sub;
```
- 这行代码的含义：**告诉 Rust：我要引入名为 `sub` 的顶层模块，自动去查找并加载它的源码**
    - 新版布局：找到 `sub.rs`，读取里面的代码、注册 `sub` 模块以及它里面的子模块（foo、bar）
    - 旧版布局：找到 `sub/mod.rs`，完成模块注册
- 只有执行完 `mod sub;`，`sub` 才成为 crate 根下合法的模块路径，后续才能被 `use` 引用
- `mod` = **模块注册声明**
- `use` = **路径导入/别名引用（仅做简写，不加载源码、不注册模块）**

#### 2. 直接写 `use sub::{foo, bar};` 为什么不行
```rust
// main.rs
// 错误写法：没有 mod sub;
use sub::{foo, bar};
```
- `use` 只是语法糖，作用是简化长路径（比如 `crate::sub::foo`），**本身不会加载源码、不会定义/注册 sub 模块**
- 编译器检索不到 `sub` 模块，会报编译错误：`error: could not find crate or module 'sub'`
- `use` 依赖模块已经存在于模块树中，不能凭空创建模块

#### 3. 两种正确写法
写法一：先 mod 声明，再 use
```rust
// main.rs
mod sub; // 注册并加载 sub 模块
use sub::{foo, bar}; // 引用已注册模块内的成员

fn main() {
    foo::do_something();
}
```

写法二：全路径写法（依然需要提前 mod sub;）
```rust
mod sub;

fn main() {
    crate::sub::foo::do_something();
}
```

#### 4. 特殊情况（不需要手写 mod）
- **库入口 lib.rs / 二进制入口 main.rs** 以外的嵌套子模块：是由父模块文件里的 `mod xxx;` 声明，而不是在根 main.rs 里重复声明
- 外部第三方 crate：用 `use crate_name::xxx` / `use ::crate_name::xxx`，配合 Cargo.toml 依赖，不需要手写 `mod crate_name;`，和本地模块不是一套机制

#### 一句话总结
- `mod sub;`：**注册 + 加载本地模块源码，把 sub 放进 crate 模块树**
- `use sub::...`：**简化访问路径，不加载源码、不注册模块**
- 本地自定义模块：必须先 `mod sub;`，再 `use`，不能跳过

#### 补充：现代写法（crate 全路径）
```rust
mod sub;
use crate::sub::{foo, bar}; // 显式根路径，可读性更好
```
