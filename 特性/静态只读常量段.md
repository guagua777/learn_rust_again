# 静态只读常量段 `.rodata` 通俗详解
## 1. 是什么
编译程序（Rust/C/C++）后，生成的可执行文件内部会划分多个**段（section）**，`.rodata` = read-only data，只读数据段。
存放**程序运行全程不变、编译期就确定**的数据：
- 字符串字面量 `"abc"`
- `static` 常量、`const` 常量
- 只读全局数组

## 2. 内存位置区分（三大区域）
1. **栈 stack**：函数局部变量，函数退出自动回收，可读可写；
2. **堆 heap**：运行时动态分配（`String`/`Vec`），手动管理生命周期，可读可写；
3. **.rodata 静态只读段**
   - 存在**可执行文件本身**里，编译阶段就把字节写死进二进制；
   - 程序启动时，操作系统把这一段映射到进程内存；
   - 内存权限：**只读**，一旦尝试修改直接触发段错误崩溃；
   - 生命周期：`'static`，程序退出才释放，全局全程有效。

## 3. 以 `let s: &str = "hello";` 举例
1. 编译时：`"hello"` 这5个字节直接打包进程序二进制的 `.rodata`；
2. 运行时：操作系统加载程序，把 `.rodata` 映射到一块只读虚拟内存；
3. 栈上变量 `s`（胖指针）保存地址 + 长度，指向这块只读内存；
4. 永远不能修改 `"hello"` 的字节，内存硬件层面禁止写入。

## 4. 和栈、堆关键差异
| 区域 | 读写权限 | 生命周期 | 数据来源 |
|------|----------|----------|----------|
| 栈 | 可读可写 | 函数局部，出函数销毁 | 局部变量、引用指针 |
| 堆 | 可读可写 | 手动/所有权回收 | String、Vec 动态内容 |
| .rodata | 仅只读 | 整个程序运行期间 | 字面量、static 常量 |

## 5. 常见存放在 .rodata 的东西
1. 所有双引号字符串字面量 `"rust"`、`"123中文"`；
2. `static NAME: &str = "test";`；
3. 全局只读数组 `static ARR: [u8;3] = [1,2,3];`；
4. 二进制内嵌的静态资源、错误提示文本。

## 6. 容易踩坑的点
### ① 不能修改 rodata 里的数据
```rust
let s = "hello";
let bytes = s.as_bytes_mut(); // 编译报错，str 只读，底层是rodata
```
硬件内存保护，不允许写入。

### ② 区分 static 与字面量，都在 rodata
```rust
static MSG: &str = "hello world"; // 字符串本体在.rodata
fn main() {
    let s = "hello world"; // 和上面是同一块rodata内存，编译器会合并重复字面量
}
```
编译器优化：重复相同字符串字面量只会在 `.rodata` 存一份，多个引用共用。

### ③ 只有字面量 &str 指向 rodata
如果 `&str` 从 `String` 切片而来，指向堆，不是 rodata：
```rust
let owned = String::from("abc"); // 数据在堆
let slice = &owned[..]; // &str 胖指针指向堆内存，和rodata无关
```

## 一句话总结
`.rodata` 是嵌入程序二进制的只读内存段，存编译期固定不变的常量字符串/数据，生命周期全局 static，不可修改，既不在栈也不在堆。
